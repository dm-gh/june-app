# An Apple Shortcut posting to a webhook is the primary way to record a Transaction

Recording a Transaction has to be nearly frictionless or it will not happen. We decided the primary capture path is an Apple Shortcut, generated by June from the User's Categories, that posts a small JSON body (amount, currency, category slug, description) to a per-User URL containing a Capture Token. The in-app form is the secondary path and the only one that can set a Wallet or Tags. We rejected making the app form primary because opening a PWA and filling fields on the phone is slower than a home-screen Shortcut, and rejected a native app because it doubles the surface for a solo developer.

## Consequences

- The capture endpoint never rejects for a bad category or an unmatched currency; it stores the Transaction as Uncategorised or Unassigned instead. It rejects only malformed bodies and invalid currencies.
- The Wallet for a captured Transaction is resolved server-side by Wallet Order, so Wallet Order is a real domain rule, not a UI nicety.
- Regenerating a Capture Token invalidates the installed Shortcut, so token rotation must be paired with re-generating the Shortcut.
- Shortcut generation and delivery is an MVP feature, not tooling.
